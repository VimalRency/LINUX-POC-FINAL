ADAS Linux Process Supervisor — Build and Validation Record
=============================================================

Changes in this revision
------------------------
- Replaced the shared volatile stop flag with a mutex-protected worker stop flag.
- Added a signal-only volatile sig_atomic_t flag. It is written by the signal
  handler and checked by the supervisor main thread; worker threads do not
  access it.
- Added thread-safe stop-flag load/store functions used by watchdog and
  resource-monitor threads.
- Reset stop state during supervisor initialization.
- Added configuration and API unit-test cases (GoogleTest).
- Added startup error-path integration tests.
- Made integration test output files unique temporary files to avoid stale
  /tmp permission/collision failures.
- Coverage target now includes startup error-path integration tests.

Important validation guidance
-----------------------------
The previous user-provided Helgrind log identified races on
supervisor_stop_requested. This revision protects the worker stop flag using
a POSIX mutex and keeps the signal-handler flag separate. This is a targeted
race correction, not a claim that Helgrind has passed. Re-run `make helgrind`
on WSL and inspect logs/helgrind.log. Require ERROR SUMMARY: 0 errors before
marking Helgrind passed.

Memcheck and Helgrind targets intentionally do not use --trace-children=yes.
They validate the supervisor process and its threads. Managed child executables
are separate programs and need their own instrumentation runs if required.
